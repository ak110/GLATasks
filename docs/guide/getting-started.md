# はじめに

タスク管理とカウントダウンタイマーを統合したWebアプリ。自前のサーバーにデプロイして利用する。

## 主な機能

- 複数リストでのタスク管理とドラッグ&ドロップによるリスト間移動
- タスクに紐付くカウントダウンタイマー（カウントダウン・アラームの2モード）
- ブラウザ内蔵AIによる翻訳ページ（入力停止後に自動翻訳。Chrome 138以降のデスクトップ版とブラウザ内蔵モデルが必要）
- タスクへのファイル添付（画像はサムネイル表示・クリックで原寸ポップアップ・クリップボード貼付に対応、
  非画像は📎アイコン表示・クリックでダウンロード）
- タスクの実行中状態と完了状態の切り替え
- TODO区分による通知バッジ表示
- 定期TODOスケジュール
- SSEによる複数端末・タブ間のリアルタイム同期
- PWA対応（オフライン画面から接続回復時に自動復帰）
- [Chrome拡張機能](./chrome-extension.md)でWebページをワンクリック保存
- [Android共有メニュー](./android-share.md)から直接タスク追加
- 品目別カロリーの記録（品目に登録しない一時項目も可）と1日当たりペース・7日間平均・28日間平均の表示（1日当たりの目標値との比較、摂取可能量の表示、目標内に収めた日の達成状況、毎日の自動記録、期間を指定した一括記録・一括削除、CSVインポート・エクスポート）

## カロリー計算

ヘッダーの「カロリー」から、摂取記録と品目を管理できる。
先に品目名、1個当たりのkcal、備考を登録し、記録へ日時、品目、数量を入力する。
各記録の行末にある「⋯」ボタンからコピー、編集、削除を選べる。
コピーを選ぶと、品目と数量を引き継ぎ、現在日時を初期値にして追加できる。
品目も行末の「⋯」ボタンから編集と削除を選べる。
記録か自動記録で使われている品目は削除できず、メニューに使用している件数を表示する。

品目に登録していない名前を品目欄へ入力すると、その記録は一時項目になり、数量欄の値をそのままkcalとして記録する。
入力中は数量欄が「kcal」欄に変わり、一時項目として記録する旨を表示する。
一覧では一時項目の名前の前に「一時」と表示し、数量の列を空欄にする。
一時項目は記録ごとに名前とkcalを持つため、後から同名の品目を登録しても、その品目のkcalとは掛け算しない。
一時項目をコピーした場合も、一時項目として追加する。
品目の記録は、編集ダイアログの「一時項目に変換」から一時項目へ変換できる。
変換後のkcalは品目のkcalと数量の積となり、確認ダイアログで「変換」を選ぶと保存する。
変換後は品目のkcalを変更しても、その記録には反映されない。

目標値は1日当たり1615 kcalが初期値である。
1日当たりペースと、直近7日間及び28日間の1日当たり平均を、目標値に対する割合とともに確認できる。
1日当たりペースのカードには、目標値までの残りのkcalと、目標値に対する割合を示すリングを表示する。
目標値を超えている場合は、超過しているkcalを表示し、リングは全周を塗る。
1日当たりペースは、摂取した直後は全量を数え、時間の経過とともに数える量を連続的に減らす（24時間後はおよそ0.37倍）。
同じ量を同じ間隔で食べ続けた場合、この値は1日当たりの摂取量と一致する。
1日当たりペースを目標値の付近に保てば、7日間平均と28日間平均も目標値へ近づく。
7日間平均と28日間平均は、それぞれ直近7日間と28日間の摂取量の合計を日数で割った値である。
各カードは1食分の目安（700 kcal）を物差しとして、目標値に対する状態を色で示す。
1日当たりペースは、目標値までの残りが1食分以上あれば緑系になり、それ以外は通常の色になる。
7日間平均と28日間平均は、1週間に1食分の差を1日当たりへ換算した100 kcalを幅とし、目標値より100 kcal以上少なければ緑系、100 kcal以上多ければ琥珀系、その間は通常の色になる。

「達成状況」には、直近28日の各日について、その日までの7日間の1日当たり平均が目標値以下だったかを、左を最も古い日、右を昨日として点で表示する。
1日は早朝4時で区切り、4時より前の摂取は前日に数える。
判定するのは昨日までの日で、今日の分は翌朝4時を過ぎてから判定する。
記録の無い日は0 kcalとして平均に含めるが、最初の記録より前の日を含む7日間は判定しない。
昨日まで続けて目標値以下だった日数を「3日連続で目標内」のように表示し、その間は枠の色が緑系に変わる。
28日すべてが目標値以下の場合は「28日以上」と表示する。
昨日までの7日平均がその前の7日平均より下がった場合は、「先週より −120 kcal/日」のように減った量を表示する。

kcalは1以上、数量は0以上の整数で扱う。数量を0にすると、その記録の摂取量は0 kcalとして集計される。

「自動記録」に時刻、品目、数量を登録すると、ONの間は毎日その時刻に記録が追加される。
時刻は登録した端末のタイムゾーンで解釈する。
OFFにしていた間に過ぎた時刻の記録は、ONへ戻しても追加されない。
サーバーが停止していた間に過ぎた時刻の記録は、再起動後にまとめて追加される。
設定の編集と削除は、行末の「⋯」ボタンから選ぶ。
自動記録の設定を削除しても、追加済みの記録は残る。

「一括操作」では、開始日から終了日までの各日に、指定した時刻、品目、数量の記録を1件ずつ追加できる。
同じ画面では、開始日から終了日までにある指定した品目の記録をまとめて削除できる。
一時項目の記録は一括削除の対象にならない。

CSVを使う場合は、品目CSVを先にインポートし、その後に記録CSVをインポートする。
記録CSVは既存の記録へ追記されるため、同じCSVを再度インポートすると記録が重複する。
エクスポートしたCSVはUTF-8 BOM付きで、品目名と備考を変換せずに保存する。
記録CSVの「一時項目」列は、一時項目の行が1、品目の行が空となり、一時項目の行の数量はkcalを表す。
「一時項目」列の無い記録CSVは、全行を品目の記録として取り込む。
このCSVをそのままインポートし直すと、文字列値は元の値のまま取り込まれる。

## デプロイ

### 前提条件

- Docker / Docker Composeがインストールされたサーバー
- HTTPS環境（リバースプロキシ等）

### 手順

1. リポジトリをクローン

   ```bash
   git clone https://github.com/ak110/GLATasks.git
   cd GLATasks
   ```

2. `.env`を作成（`.env-example`を参考に）

   ```bash
   cp .env-example .env
   ```

   `DATA_DIR`にデータ保存先ディレクトリのパスを設定する（`COMPOSE_PROFILE`は`production`を推奨）

3. 起動

   ```bash
   make deploy
   ```

4. HTTPSでアクセスできるようリバースプロキシを設定
  （設定例は[アーキテクチャの外部リバースプロキシ設定](../development/architecture.md#外部リバースプロキシ設定)を参照）

5. ブラウザでアクセスし、ユーザー登録してログイン

### 停止

```bash
make stop
```

### 更新

最新版に更新する場合:

```bash
git pull
make deploy
```
