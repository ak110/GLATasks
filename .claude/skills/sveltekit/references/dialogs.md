# ダイアログと画面コンポーネント

## ダイアログ

共通のDialogがHTMLの`dialog`要素を`showModal()`で開く。
Dialogがフォーカスの移動、Tabの循環、背景の操作抑止、閉じた後のフォーカス復帰を担当する。
各ドメインのダイアログは内容と確定操作を担当する。

- `globalThis.confirm`、`globalThis.prompt`、`globalThis.alert`の代わりに`ConfirmDialog`と`PromptDialog`を使う
- 確認・入力ダイアログは`onCancel`、`onConfirm`、`onSubmit`を使い、汎用ダイアログの`onClose`とは区別する
- 汎用ダイアログはタイトルと閉じるボタンを持つ。確認・入力ダイアログはキャンセルボタンを持てる
- タイトルの見出しを`aria-labelledby`で参照し、タイトルが無い場合は`aria-label`を指定する
- ネストしたダイアログは後から`showModal()`で開き、top layerの順序を使う
- Escapeは最前面のダイアログだけを閉じる。ドメインのwindow keydownで重ねて処理しない
- ダイアログを開いている間は接続回復による自動リロードを抑止する
- アクセシブル名や入力のラベルを変える前に、コンポーネントテストとPlaywrightの`getByRole`と`getByLabel`の期待値を確認する

確認、入力、画像拡大、リストのマージ、定期TODO、タイマー作成、タスク編集、カロリー編集で同じDialogを使う。
TabとShift+Tabの循環、閉じた後のフォーカス復帰、ネストしたEscapeの動作は実ブラウザーで確認する。

## メニュー、バナー、添付

メニューの表示、外側クリック、項目の選択後の閉じ方は共通のMenuへ集約する。
更新と接続回復の案内は共通のBannerを使う。
メニュー、バナー、Toastなどの重なり順とボタン・入力欄のクラスは共通定義を使い、画面ごとに数値と文字列を再定義しない。

添付ファイルのサムネイル、画像の読み込み失敗、ファイル選択、ドロップ、貼り付けは共通処理を使う。
タスクのメモが省略されているかの判定とサイズ変更の監視も共通処理を使う。
各コンポーネントのpropsは`interface Props`で定義し、`let { ... }: Props = $props()`で受ける。
